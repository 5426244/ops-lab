# SQL 第 1 天 · 10 题答案与验证

先切库，每条都要有分号：

```sql
USE opslab;
```

数据规模：`dept` 5 行，`emp` 20 行。

## Q1 查所有员工

```sql
SELECT * FROM emp;
```

预期：20 行，`emp_id` 从 1 到 20。

## Q2 查薪资高于 15000 的员工姓名和薪资

```sql
SELECT emp_name, salary
FROM emp
WHERE salary > 15000;
```

预期 7 行：赵强 21000、周涛 16000、郑凯 19200、陈杰 25000、褚磊 18000、沈悦 22000、许峰 17000。

## Q3 查运维部（dept_id = 10）的所有员工

```sql
SELECT emp_name, salary
FROM emp
WHERE dept_id = 10;
```

预期 6 行：张野 12000、李明 15000、王芳 9800、赵强 21000、孙悦 13500、许峰 17000。

## Q4 按薪资从高到低，取前 3 名

```sql
SELECT emp_name, salary
FROM emp
ORDER BY salary DESC
LIMIT 3;
```

预期：陈杰 25000、沈悦 22000、赵强 21000。

`DESC` = 降序，不写就是升序；`LIMIT 3` = 只要前 3 行。

## Q5 统计每个部门的人数

```sql
SELECT dept_id, COUNT(*) AS 人数
FROM emp
GROUP BY dept_id;
```

预期：10 → 6，20 → 4，30 → 5，40 → 2，50 → 3。

`AS 人数` 是给这列起别名，不起也能跑，只是列名会显示成 `COUNT(*)`。

---

## Q6 统计每个部门的平均薪资，只显示平均薪资大于 13000 的

```sql
SELECT dept_id, AVG(salary) AS 平均薪资
FROM emp
GROUP BY dept_id
HAVING AVG(salary) > 13000;
```

预期 3 行：10 → 14716.67，20 → 13750，30 → 17800。

**这题是 WHERE 和 HAVING 的分界点**：
- `WHERE` 在分组**之前**筛行（筛员工）
- `HAVING` 在分组**之后**筛组（筛部门）

写 `WHERE AVG(salary) > 13000` 会直接报错——分组前的 WHERE 还不知道平均值是多少。

## Q7 查每个员工的姓名和所属部门名

```sql
SELECT e.emp_name, d.dept_name
FROM emp e
JOIN dept d ON e.dept_id = d.dept_id;
```

预期 20 行。

`emp e` / `dept d` 是给表起短名，因为两张表都有 `dept_id`，不写前缀 MySQL 不知道你要哪张表的。

## Q8 列出每个部门名称和人数，没有员工的部门也要显示

```sql
SELECT d.dept_name, COUNT(e.emp_id) AS 人数
FROM dept d
LEFT JOIN emp e ON d.dept_id = e.dept_id
GROUP BY d.dept_name;
```

预期 5 行：运维部 6、安全部 4、研发部 5、行政部 2、测试部 3。

**注意 `COUNT(e.emp_id)` 不是 `COUNT(*)`**：
- 部门没员工时，`LEFT JOIN` 会补一行，`e.emp_id` 是 `NULL` → `COUNT(e.emp_id)` 数 0
- 写成 `COUNT(*)` 会数成 1（因为它数的是"行数"，NULL 那行也算一行）

当前数据里 5 个部门都有人，所以两种写法结果一样。想看出差别，加一个空部门：

```sql
INSERT INTO dept VALUES (60, '新部门', '北京');
```

再跑一次 Q8，`COUNT(e.emp_id)` 得 0，`COUNT(*)` 得 1。看完把这条删掉：

```sql
DELETE FROM dept WHERE dept_id = 60;
```

## Q9 查薪资高于公司平均薪资的员工

```sql
SELECT emp_name, salary
FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);
```

预期 9 行：李明 15000、赵强 21000、周涛 16000、郑凯 19200、陈杰 25000、褚磊 18000、卫兰 14500、沈悦 22000、许峰 17000。

公司平均 = 280000 / 20 = 14000。

括号里那个 `SELECT` 先单独跑一遍，确认它返回 14000：

```sql
SELECT AVG(salary) FROM emp;
```

**这就是子查询**：先把内层算出一个值，外层拿它当条件。

## Q10 查 2025 年入职的员工

```sql
SELECT emp_name, hire_date
FROM emp
WHERE hire_date >= '2025-01-01'
  AND hire_date <  '2026-01-01';
```

预期 4 行：韩梅 2025-02-14、冯雪 2025-04-22、王芳 2025-09-01、朱琳 2025-12-25。

**别写 `YEAR(hire_date) = 2025`**：能跑，但函数套在列上会让索引失效，20 行看不出区别，200 万行就是几十秒 vs 几毫秒。

## 一页速查

| 想干什么 | 写在哪个位置 |
|---|---|
| 筛行 | `WHERE 条件`（GROUP BY 之前） |
| 筛组 | `HAVING 条件`（GROUP BY 之后） |
| 排序 | `ORDER BY 列 DESC` |
| 取前 N | `LIMIT N` |
| 关联两张表 | `JOIN 表 ON 关联字段` |
| 保留左表全部 | `LEFT JOIN` |
| 用另一个查询的结果当条件 | `WHERE 列 > (SELECT ...)` |
| 子句顺序 | `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT` |
