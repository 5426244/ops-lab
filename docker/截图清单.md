# Docker 截图清单

> 全部用**最终跑通的状态**截。
> 一张图 = 一条命令 + 它下面的输出，别把命令单独截。
> 命名按表格右列，编号连起来看就是一条完整链路。

---

## 先统一环境

每次开新终端先跑这条，后面的命令都在这个目录里执行。

```bash
cd ~/ops-lab/docker/myweb
```

| 行 | 敲/粘 | 干什么 |
|---|---|---|
| 1 | **敲** | 进项目目录，`docker build .` 的 `.` 指的就是这里 |

## 截图 01：菜谱和产物

```bash
cat Dockerfile && sudo docker images | grep myweb
```

| 项 | 内容 |
|---|---|
| 文件名 | `01-dockerfile-与镜像.png` |
| 应该看到 | Dockerfile 两行（`FROM nginx` / `COPY ...`）+ 镜像列表里的 `myweb:v2` |
| 证明什么 | 「我写的这份菜谱，做出来的是这个镜像」 |

| 行 | 敲/粘 | 关键部分 |
|---|---|---|
| 1 | **敲** | `&&`=前一条成功才跑后一条；`\|`=管道；`grep`=过滤 |

## 截图 02：构建过程

```bash
sudo docker build -t myweb:v2 .
```

| 项 | 内容 |
|---|---|
| 文件名 | `02-docker-build.png` |
| 应该看到 | 一堆 `CACHED`（缓存命中），最后 `naming to docker.io/library/myweb:v2` |
| 证明什么 | 「镜像是一层层构建出来的，改哪层只重建哪层」 |

| 行 | 敲/粘 | 关键部分 |
|---|---|---|
| 1 | **敲** | `-t`=给镜像起名；**最后的 `.` 是构建上下文，不能丢** |

**想要完整重建过程（不用缓存）：**

```bash
sudo docker build --no-cache -t myweb:v2 .
```

| 行 | 敲/粘 | 关键部分 |
|---|---|---|
| 1 | **敲** | `--no-cache`=强制重新拉取每一层，会慢十几秒 |

## 截图 03：容器在跑 + 页面正确

```bash
sudo docker ps --filter name=final && curl http://127.0.0.1:8096
```

| 项 | 内容 |
|---|---|
| 文件名 | `03-docker-run-验证.png` |
| 应该看到 | `final` 那行 `Up ... 0.0.0.0:8096->80/tcp`，下面 `<h1>Hello from 张野的镜像 </h1>` |
| 证明什么 | 「容器在运行 + 端口映射生效 + 页面是我写的」 |

| 行 | 敲/粘 | 关键部分 |
|---|---|---|
| 1 | **敲** | `--filter name=final`=只列这个名字的容器；`curl`=发 HTTP 请求 |

## 截图 04：镜像分层

```bash
sudo docker history myweb:v2
```

| 项 | 内容 |
|---|---|
| 文件名 | `04-docker-history.png` |
| 应该看到 | 最上面是 `COPY`（几小时前，你加的，几十字节），下面一行行全是 11 天前的 nginx 官方层 |
| 证明什么 | 「我的镜像 = 官方层 + 我自己加的一层」 |

| 行 | 敲/粘 | 关键部分 |
|---|---|---|
| 1 | **敲** | `history`=列出镜像的每一层及其来源命令 |

**注意看 `EXPOSE map[80/tcp:{}]` 这一行 —— `-p 8096:80` 里的 80 不是随便写的，是镜像声明的。**

## 构图三条铁律

**1. 命令和输出要在同一张图里**

```bash
docker ps && curl http://127.0.0.1:8096
```

比分开截两张更有说服力。

**2. 别把提示符滚出画面**

截图前先 `clear`，让命令在屏幕靠上位置。

**3. 报错图单独存**

早上 `index.htlm` 那张构建失败图，放进 README 的「踩坑」一节，不要混进 screenshots。
