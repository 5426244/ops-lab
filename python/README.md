# python/

用 Python 写的运维小工具。

---

## port_scan.py

批量探测一组端口是否开放，不依赖 nmap。

```bash
python3 port_scan.py                 # 扫本机
python3 port_scan.py 192.168.59.130  # 扫靶机
```

### 实测输出（扫 Metasploitable2 靶机）

```
目标: 192.168.59.130
------------------------------
[开放] 21
[开放] 22
[开放] 23
[开放] 80
[开放] 1524
------------------------------
共扫描 5 个端口，开放 5 个
开放的端口: [21, 22, 23, 80, 1524]
```

`1524` 就是 Metasploitable2 故意留的未授权 root shell 端口——11/11 用 `nc -nv 192.168.59.130 1524` 进过 root。
**这个脚本自己把它扫出来了。**

扫本机时是另一组结果：`22 / 80 / 3306` 开放，`443 / 8080 / 1524` 关闭，与 `ss -tlnp` 看到的监听状态一致。

---

### 脚本结构

| 部分 | 作用 |
|---|---|
| `PORTS = [...]` | 要扫的端口列表，改这里就换目标 |
| `check_port(host, port)` | 连一个端口，返回 `True` / `False` |
| `main()` | 读命令行参数、循环调用、打印统计 |
| `sys.argv[1] if len(sys.argv) > 1 else "127.0.0.1"` | 不给参数时默认扫本机 |

---

### 核心就四行

```python
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.settimeout(1.0)
code = s.connect_ex((host, port))
s.close()
```

| 行 | 干什么 |
|---|---|
| `socket()` | 新建一条 TCP 连接（一根电话线） |
| `settimeout(1.0)` | 最多等 1 秒，不回就当失败 |
| `connect_ex(...)` | 拨号，**返回数字而不是抛异常** |
| `close()` | 挂断 |

**返回 `0` = 连上了 = 端口开放；其他数字 = 连不上 = 端口关闭。**

---

### 为什么用 `connect_ex` 而不是 `connect`

`connect` 连不上会直接抛 `ConnectionRefusedError`，脚本当场崩。
`connect_ex` 把结果变成一个返回值，脚本能继续扫下一个。

**扫 6 个端口，一半关着——用 `connect` 扫到第一个关的就停了。**

---

### 为什么每个端口都要新建 socket

一个 socket 连上之后，这通“电话”就对端固定了，不能再拨别的地址。
复用同一个 socket 去连第二个端口，得到的结果不可信——**实测出现过 6 个端口全返回 0 的假象。**

所以 `check_port()` 每次都新建、用完 `close()`。

---

### 三个坑

**1. 复用同一个 socket**
现象：所有端口都显示“开放”。
原因：`connect_ex` 在已连接的 socket 上行为异常。
改法：每个端口新建 socket，测完 close。

**2. 不写 `settimeout`**
现象：扫到某个端口时卡住几分钟不动。
原因：目标不回包时会一直阻塞，等内核超时（通常 2 分钟以上）。
改法：`settimeout(1.0)`，扫描脚本必须设超时。

**3. 改完 PORTS 没保存就重跑**
现象：改了列表但输出还是旧的。
原因：编辑器没保存，或跑的是另一份副本。
改法：改完先 `cat port_scan.py | head -8` 确认。
